## 设计特异性判断

**结论：视觉是"长出来的"，信息架构还带着通用 dashboard 味。**

- 视觉层：石墨灰纸面 + 青绿/金色数据光、TIMESLOT 字标、金色楔形时间母题、圆体等宽计时数字，是明确的"精密仪器工作台"世界，换成任何别的产品都不成立。
- 结构层：首页 = 趋势图 + KPI 卡 + 日历热力图 + 读数列表，这套骨架任何效率工具都能直接套用；"读数/信号/工作台"的仪表腔调不是从备考流程里长出来的。
- 真正属于时隙的：目标倒计时与专注沉淀的联动（倒计时主卡 + 周目标 + 科目分布）、北京时间纪律、楔形时间标记。这些应该承担更多叙事。

## Overall Impression

一眼看去是克制、可信、有身份的工具；最大的机会不在加装饰，而在"编辑"：删掉重复的读数、把主行动顶出来、让全景页真的讲时间。把首页从记分牌改成仪表盘，整体质感会再上一档。

## What's Working

1. **状态反馈完整**：计时进行中有 RUNNING 指示、状态胶囊、实时读数；小组件显示"最近同步于 9:39"；删除/清空都有 8 秒撤销横幅。
2. **数据诚实**：图表注明"进行中的计时停止后才计入""含零投入日期"，周目标卡注明统计口径，不制造虚假进度。
3. **图表可读也可达**：投入趋势的 BarMark 带 accessibilityLabel，AX 树能逐日读出"2026年9月13日，7小时59分"；数据配色区分度高（暗色下 5.2–8.4:1）。

## Priority Issues

### [P1] 首页把同一个数字讲了四遍
- **证据**：首页同时出现"本周学习节奏 27 小时 32 分"、"当前专注 本周 27.5/56 小时"、"本周目标 27.5 小时 / 目标 56 小时"、"工作读数·本周累计 27.5 小时"；"今日投入 0 分钟"与"工作读数·今日专注 0 分钟"重复。见 CountdownWidgetApp.swift:702、:869、:925 附近与 homeVisualOverview。
- **为什么伤用户**：眼睛没有锚点，每次扫视都要重新判断哪个才是"现在该看的数"；备考用户最关心的"今天 vs 目标"被稀释。
- **改法**：一屏只保留一个"今日"、一个"本周"、一个"目标"：学习节奏卡管周趋势、今日投入卡管今天、周目标卡管达标进度；"工作读数"删掉今日专注/本周累计两行，只留连续专注与高效时段（或整块并入右侧）。
- **建议命令**：$impeccable distill

### [P1] 主行动不突出：专注页三个同款幽灵按钮
- **证据**：重置/暂停/停止都是 inkPill + 13pt 文字 + 相近内边距（PomodoroViews.swift:920–975）；开始/暂停文字还用 .primary.opacity(0.82)。首页也没有"开始/继续专注"的主按钮，只有一个箭头跳转。
- **为什么伤用户**："开始学习"是产品的心脏，现在和次要动作同权，用户需要先找再点。
- **改法**：开始/暂停改为实心或描边强调色、更大点击区，成为唯一 primary；停止/重置维持幽灵样式；首页"当前专注"卡直接放一个"开始/继续"按钮。
- **建议命令**：$impeccable layout（配 bolder 定权重）

### [P1] 统计页把周目标折进折叠组，"记录范围"有 6 个同级选项
- **证据**：`DisclosureGroup("原始记录与周目标")` 默认收起（PomodoroViews.swift:1026，状态定义 :323）；记录范围有 全部/今天/按周/近7天/本月/自定义 六项同级分段（PomodoroViews.swift:1440 起）。
- **为什么伤用户**：PRODUCT.md 原则 3 是"进度必须可见"，周目标却要展开才能看到；六路筛选在读数之前先要用户做决定，超过 ≤4 的工作记忆阈值。
- **改法**：把"本周专注目标"卡移出折叠组、放到统计页顶部；折叠组只留原始记录；范围收敛为 本周/近7天/本月/自定义 四项，"全部"放进更多菜单。
- **建议命令**：$impeccable distill

### [P2] 浅色模式下数据色当文字用，对比度不达标
- **证据**（WCAG 计算值，浅色画布 #F7F7F8 / 卡片 #FDFDFD）：teal 2.60 / gold 2.23 / coral 3.21 / moss 2.75 / indigo 3.33 / rose 3.15 / 系统绿 2.07 : 1，全部低于正文 4.5:1，多数低于图形 3:1。使用位置如 CountdownWidgetApp.swift:703（本周学习节奏标签用 teal）、周目标卡的 gold 数字、PomodoroViews.swift:1192（绿色达标数字）与图表系列色。暗色模式 5.2–8.4:1 合格。
- **为什么伤用户**：浅色用户看到的是"发灰的强调色"，图表系列彼此趋同；低视力用户直接读不清。
- **改法**：给数据调色板补 light/dark 两档（像 ColorPreset 那样切换）：浅色档整体压暗到 ≥4.5:1（如 teal→#2F7A6F、gold→#8A6A22），文字一律用压暗档，亮档只用于大色块/图形；浅色下不要用系统 `.green` 做文字。
- **建议命令**：$impeccable colorize（配合 audit 复核）

### [P2] 无障碍：首页对 VoiceOver 基本是空白
- **证据**：AX 树里首页只有一个无子元素的滚动区（导航 rail + 标题 + 桌面小组件按钮可见），而倒计时/专注/设置页能暴露完整控件与数值；首页图例字号下探到 10pt（AppType.caption(10)）。图表本体有 accessibilityLabel，属于优点。
- **为什么伤用户**：VoiceOver 用户打开默认页面读不到任何目标、进度与今日投入；键盘用户也无法操作统计页的自定义分段与图表点选。
- **改法**：给首页各卡片补 accessibilityElement(children: .combine) 与整卡 label（"本周专注 27.5 小时，目标 56 小时，完成 49%"）；统计筛选补键盘快捷键或方向键切换；图例最小字号提到 11pt。
- **建议命令**：$impeccable harden

## Persona Red Flags

**Alex（效率型）**：统计页六路范围筛选没有键盘路径；计时中连"切任务"这种明显意图都被禁用；"清空全部"藏在折叠组里，批量整理记录要展开两次。

**Jordan（第一次用）**：左侧 rail 只有图标没有文字（悬停才有 tooltip）；"工作读数、信号、已固定、时间流全景、节奏"这些词需要翻译；首页给了 9 个数字，却没有一句"先做什么"。

**Sam（无障碍/键盘/低视力）**：首页 AX 基本为空，VoiceOver 打开即迷路；浅色模式强调色 2.1–3.3:1；10pt 图例加 secondary 文字是双重困难。

**备考中的 Koko（项目画像）**：想一眼看到"今天/本周 vs 目标"和"现在该干什么"；目前这三个答案散在四处且互相重复。

## Minor Observations

- 时间流全景只有一条列表行 + 大片空白，没有时间轴；建议画真实时间横轴（今天→未来数月）或直接并入目标列表并改名"全部目标"。
- DesignTokens.swift:842 的 StarField（0.3s 闪烁星点）是死代码，注释里的"Moonshot 宇宙质感"与既定"精密仪器工作台"方向冲突，建议删除。
- 设置有两个入口（rail 的设置页与 ⌘, 独立设置窗口），同一页面两处入口，建议保留一个主入口并在另一处做跳转。
- 首页卡片仍用硬编码底色（CountdownWidgetApp.swift:735 附近 `.white.opacity(0.04/0.85)`），未走 Surface/cardSurface 令牌，长期会漂移。
- 大字号字距偏保守：pageTitle(30) 用 0 字距，计时数字用 +0.2；可对 30pt+ 收负字距、计时数字归零，更"仪表"。
- 倒计时页头部一行 7 个控件（切换目标/正在倒计时/已固定/暂停/编辑/新建/更多），"已固定"这类状态建议降级为图标 toggle。
- 阶段记录按钮"清空全部"是低权重文本样式，却执行不可逆批量删除；建议弱化位置但保持 destructive 语义提示。

## Questions to Consider

- 如果首页只允许保留一个数字和一个按钮，你会留什么？
- "工作读数/信号"这些词是在帮用户理解，还是在满足仪表盘的自我想象？
- 时间流全景如果能只回答一个问题，应该是"什么时候到期"还是"接下来该做什么"？

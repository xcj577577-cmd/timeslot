# Windows 版移植方案（决策记录）

状态：v1 草案（2026-08-31）。本文回答三个问题：用什么技术栈、哪些东西能共享、按什么顺序做。

## 目标界定

「Windows 兼容」分三层，逐层交付：

1. **数据互通**：Windows 端可导入/导出 macOS 版备份（见 [DATA_FORMAT.md](DATA_FORMAT.md)）。
2. **功能对齐**：倒计时、番茄钟/正计时、专注统计三大看板在 Windows 上的原生实现。
3. **体验对齐**：桌面小组件驻留桌面层（Windows 上没有 WidgetKit 对等物，需要自建）。

## 技术栈决策

**推荐：WinUI 3（Windows App SDK）+ C#/.NET 8。**

理由：

- 原生 Fluent 控件与 graphite 设计语言同源，观感不输 macOS 版（这台机器上唯一能做到「不像移植」的选项）。
- 桌面小组件可落地的唯一原生路线：透明置顶窗口自绘（Windows 11 没有桌面小组件表面，Widgets 面板是网页卡片，不可用）。
- MSIX 打包 + 商店/直装分发成熟；后台任务（计时提醒、Toast 通知）系统级支持。

备选与否决：

| 方案 | 结论 |
| --- | --- |
| Flutter | 一套码多端，但桌面观感偏"应用画像"，与原生优先的产品原则冲突 |
| Tauri (Rust + Web) | 体积小，但 UI 是 Web 技术栈，观感与手感达不到 macOS 版标准 |
| Compose Multiplatform | 桌面端尚不成熟，JVM 运行时重 |

代码层面**不共享代码，共享契约**：Swift 包不跨平台，把「数据格式 + 核心规则」写成规范与测试向量（见 DATA_FORMAT.md），两边各自实现并对拍。

## 核心规则清单（需要与 macOS 版对拍的行为）

- 倒计时数学：进度 = (totalDuration − 剩余) / totalDuration；暂停冻结剩余、目标日不漂移。
- 番茄钟状态机：专注/短休/长休 + 每 N 轮进长休；阶段中锁定任务；「停止」入账、「重置」不入账。
- 统计边界：一切日期按 Asia/Shanghai；周边界为周一至周日；跨午夜记录按实际时间拆分归属。
- 备份：导出/导入语义与自动备份前置（DATA_FORMAT.md「导入语义」）。

## 没有 Windows 机器怎么开发

1. **GitHub Actions `windows-latest` 当构建机**（推荐起步，零硬件成本）：`msbuild`/`dotnet publish` 构建 WinUI 3，产物上传 artifact；单测全量可跑。迭代慢，但 M1 阶段（核心库 + 数据层）完全够用。
2. **Parallels Desktop / UTM 装 Windows 11 ARM**（进入 UI 阶段后必备）：Apple Silicon 上运行成熟，Visual Studio 2022 支持 ARM64，本地即时调试。
3. 真机（可选，分发验证阶段再说）。

## 里程碑

- **M0 契约与决策**（已完成）：本文档 + DATA_FORMAT.md。
- **M1 核心内核**：C# 类库实现倒计时/番茄钟/统计规则 + 备份 JSON 读写，配对拍测试（用 macOS 导出的真实备份做 fixture）；加一个 CLI 校验工具。可在 CI 上完成。
- **M2 三看板 UI**：首页/倒计时/专注按 graphite 设计语言在 WinUI 3 重绘。
- **M3 桌面小组件**：透明置顶窗口方案（倒计时/番茄钟/本周目标），秒级刷新用文本直绘。
- **M4 分发**：代码签名证书 + MSIX；README 增加双平台下载。

## 风险与取舍

- 桌面小组件在 Windows 上无系统级支持，自绘方案要处理全屏应用遮挡、DPI、开机自启，是最大的工程量。
- 通知与提醒走 Toast，行为与 macOS 通知对不齐属预期，不强求一致。
- 两端数据以「备份文件」为唯一互通渠道，不做实时同步（与「无账号无网络」原则一致）。
